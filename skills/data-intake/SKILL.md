# data-intake｜数据导入与核查技能

## 适用条件

拿到一份新数据文件（CSV/TSV/无表头文本）准备进入分析。核心职责：**解析正确 +
语义正确 + 类型显式**。本项目两个数据包的 T1/H1 都由本技能主导。

## 输入契约

- 数据文件路径（raw/ 下的文件一律只读）
- 变量字典路径（`metadata/data_dictionary.csv`，如存在）
- 可选：已知分隔符/表头状态；未知则先探测（读原始字节，不猜）

## 工作步骤

1. **原始字节检查**（先于任何解析器）：head 原始文件，人工确认分隔符、表头、
   引号包裹情况。**本项目教学锚点**：student-por.csv 的 G1/G2 在 raw 里带引号，
   标准 CSV 解析器会静默吸收为整数——不查原始字节就永远发现不了；
2. **受控解析**：按探测结果选择 read_csv 参数（sep/header/names/na_values），
   一次性读入；禁止 try-sep 循环猜测式解析；
3. **类型断言**：逐列对照数据字典断言 dtype，失败即停（不静默强转；如需强转，
   在质量报告中留痕说明依据）；
4. **审计调用**：运行 `python tools/data_audit.py <csv> --sep ';' [--no-header --names …]`，
   得到行/列规模、缺失、重复、取值域、IQR 异常计数（stdout 为结构化 JSON）；
5. **语义抽查**：抽 3 行人工读值，对照字典含义解释（"GP 是哪所学校""num=2
   表示什么"），语义对不上即停下报告。

## 输出

- 质量审计 JSON（tools/data_audit 产物 + 类型断言记录 + 字节检查记录）
- 问题清单（按 阻断/警告/备注 分级）

## 验证条件

- 行列数与来源声明一致（por 649×33、cleveland 303×14）；
- 每列 dtype 与字典一致，或有留痕的显式转换记录；
- cleveland 的 "?" 必须进缺失审计（ca=4、thal=2 是协议预期值）。

## 失败处理

- 解析失败 → 输出错误行号与前 3 行原文，给修复建议，不静默跳行；
- 字典缺失 → 生成空字典模板要求人工补齐，禁止凭猜测命名变量。
