# data-quality｜数据质量决策技能

## 适用条件

data-intake 审计发现问题之后、正式分析之前。职责是**做出可辩护的质量决策并留痕**，
不是把数据"洗干净"了事。

## 输入契约

- data-intake 的审计 JSON
- 协议（protocol.md）中预登记的预处理规则——协议没写的处理一律不允许现场发明

## 决策规则（项目级硬约束）

| 问题 | 允许 | 禁止 |
|---|---|---|
| 完全重复行 | 报告计数（por 实测 0） | 未留痕删除 |
| 单元格缺失 | 按协议：cleveland 完整案例法（297/303，剔除数入报告） | 静默填补、静默删行 |
| 异常值（IQR 外） | 报告并保留；做含/不含敏感性分析 | 无依据删除 |
| 哨兵值（"?"、空串） | 进缺失统计（ca/thal 的 "?" 是缺失不是水平） | 当作合法类别 |
| 样本独立性 | 两课程数据不合并（382 名学生重叠） | 合并后当独立样本 |

## 工作步骤

1. 逐项对照审计 JSON 与协议规则，输出"决策记录"（每条：问题→规则→动作→证据行号）；
2. 需要转换的（如标签二元化 num∈{1,2,3,4}→1），**规则显式写入结果 JSON** 的
   `label_mapping` 字段，随每个结果输出；
3. 生成 `quality_report`（可追加进 results.json 的 `t1_audit`/`h1_audit` 段）。

## 输出

- 质量决策记录（结构化，含每条的证据）
- 处理后样本量链：原始 n → 剔除 n → 分析 n（如 303 → −6 → 297）

## 验证条件

- 每个决策能在协议里找到依据，或被标记为"协议外新增"并给出理由；
- 分析样本量链完整可复算。

## 失败处理

- 协议与数据现实冲突（如协议预期缺失 0 但实测 6）→ 停止，报告冲突，建议修订协议
  并升版本号，**不静默按新现实处理**。
