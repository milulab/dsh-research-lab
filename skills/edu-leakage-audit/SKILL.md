# edu-leakage-audit｜教育数据泄漏审计技能

## 适用条件

任何"预测学业表现"的教育建模任务。教育数据几乎总包含 G1/G2 式的中间成绩，
这是教育数据科学最常见、最隐蔽的泄漏源。

## 核心教义（三条）

1. **泄漏是任务定义错误，不是模型错误**：把 G1/G2 放进"开学时预测期末"的
   模型，改变的是"什么时候能做这个预测"，不是模型好坏；
2. **对照实验是唯一正解**：同一协议下跑 M1（不含中间成绩）与 M2（含），
   本项目实测 Δ调整R²=+0.587（0.263→0.850）——巨大的"提升"全部来自
   信息时点，必须先问"这个预测在什么时点可用"；
3. **叙述纪律**：含中间成绩的模型只允许表述为"期末解释/含泄漏对照"；
   面向真实早期预警场景必须以 M1 类模型为准并报告其上限。

## 工作步骤

1. 列出数据字典中所有"时间晚于研究问题设定时点"的变量（本项目：G1/G2）；
2. 跑 M1/M2 对照（run_t1_t5.py 已内置），产出对照表（系数+R²+Δ）；
3. 审计学员模型：检查特征清单中是否混入中间成绩/同期结果变量；
4. 输出审计结论：任务定义声明 + 合规特征清单 + 建议的早期模型上限。

## 验证条件

- 每个交付模型有显式"任务定义"一句话（何时可用、回答什么问题）；
- M2 数字只出现在"泄漏对照"段落，不出现在效应解读段。

## 失败处理

- 学员把 M2 解读为"学习时间效应消失/变强" → 纠正：M2 中 studytime 系数变化
  反映的是与 G1/G2 的共线吸收，不是因果变化；效应解读只看 M1。
